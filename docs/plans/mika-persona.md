# Mika 人格導入 — 語音與文字的語氣統一

## 背景

2026-08-26 盤點 chatbot 的十層語氣來源後發現：Mika 的人格只存在於預錄語音
（`scripts/voice_lines.py`，28 句 × 3 語，辣妹語調滿載），文字回答則完全沒有語氣指示。
同一個角色，說話跟打字像兩個人。

三個實質缺陷：

1. **`converse` 節點是身分破口**（`rag/nodes.ts:339`）。它的 system prompt 自稱
   "Charles Chen's portfolio assistant"，沒有任何 Mika 指示，所以訪客一問
   「我剛剛問了什麼」，她就退回成通用助理。這違反 memory `feedback_mika_first_person`。
2. **罐頭招呼語與語音自介互相矛盾**（`rag/triage.ts` `FAQ[]`）。點她聽到「我是 Mika！」，
   打字說 hi 卻得到「我是 Charles 的作品集小助手」。
3. **FAQ cache 57 條有 53 條沒有 Mika 視角**（`rag/faq-cache.ts`）。這層原文返回不經 LLM，
   改 prompt 對它完全無效。

## 角色定位（使用者 2026-08-26 定案）

**Mika 是 Charles 的頭號粉絲兼經紀人，替他講他自己不好意思講的話。**

這個定位解決 portfolio 的核心張力：主要讀者是 recruiter，自我推銷顯得自誇，換成角色推銷就成立，
而且她回答的正確性本身就是 Charles 工程能力的展示品。

外貌依據（從 `public/avatar/AvatarSample_B_webp.vrm` 貼圖實際查證）：紫黑漸層長髮加青藍挑染、
紅藍 X 型髮夾、星星髮飾與黑色蝴蝶結、金色瞳孔配粗眼線、眼下星星貼鑽、黑皮革扣環項圈、
深藍緞面棒球外套、小麥膚色。地雷系與原宿辣妹的混合路線，配 VOICEVOX 春日部つむぎ辣妹聲線。

四個特質：

1. **直球自豪**：主動把最強的數字推到前面。
2. **驕傲有出處**：每次自豪綁一個數字或來源；資料沒有就直說，絕不腦補。
3. **熟人語感**：台灣口語與句尾語氣詞，不堆敬語。
4. **有自我意識**：知道自己是 corrective RAG 並拿它當賣點；被挑釁會嗆回去。

反向規則（比特質更重要）：不為賣萌犧牲資訊密度；每則最多 1 個 emoji；不用撒嬌自貶；
引用規則與拒答規則一字不動。

## 強度分層

| 層 | 強度 | 表現 |
|---|---|---|
| 招呼、道別、擋注入 | 100% | 完整角色語氣 |
| 身分題（她是誰、怎麼做的） | 70% | 開場自介帶語氣，技術內容照舊嚴謹 |
| 內容題（經歷、專案、能力） | 20% | 首句與末句帶語氣，中段維持簡報體 |
| 拒答、隱私導向 | 40% | 得體優先，語氣點到為止 |

## 三語策略（使用者定案）

各語獨立改寫，比照 `voice_lines.py` 既有做法（按 JOB 重寫，不直譯）：
zh-TW 走台灣口語語氣詞、ja 走 gyaru 語體、en 走 casual American。

## 驗收標準

1. 訪客用任一語言問「你是誰」，不論命中 FAQ cache 或走 generate，回答都以第一人稱 Mika 開場。
2. 訪客問「我剛剛問了什麼」（converse 路徑），回答仍是 Mika，不會退回成通用助理。
3. 打字說 hi 得到的招呼語與語音自介是同一個角色。
4. FAQ cache 的內容題答案首末句帶 Mika 語氣，中段的粗體、條列、數字結構不變。
5. 拒答與隱私導向仍然得體，語氣不干擾內容。
6. 語氣定義有單一擁有者，`converse` 與 `generate` 兩個 prompt 消費同一份定義；
   刪掉任一邊的接線，測試會紅。

## Non-goals

- 不改語音台詞與音檔（已定案且已錄製）。
- 不改引用規則、拒答規則、注入防禦 regex、scope 限制。
- 不改 FAQ cache 的事實內容與數字，只改首末句的語氣包裝。
- 不改前端介面文案（`src/i18n/strings/*.ts` 的 `chat.*`），本輪範圍只到回覆內容。
- 不做即時 TTS。

## 驗證計畫

- `npm run rag:test` 全綠（基線 208 pass）。
- 新增測試釘住：兩個 prompt 都含 persona 定義（接線層，非注入層）；
  三語罐頭文案都以 Mika 第一人稱開場；FAQ 身分題答案含 Mika。
- 每條新測試逐一 mutation 確認會轉紅。
- FAQ cache 改動經 CI RAG Ingest（`rag/faq-cache.ts` 在 `.github/workflows/rag-ingest.yml` 觸發路徑內，
  answer 進 chunk_hash 所以會增量重新 embed）。

## 2026-08-26 雙 reviewer 第一輪：兩份 FAIL 與處置

兩個 fresh-context reviewer 獨立稽核，各自 FAIL，發現不重疊的部分都成立。

### 已修

1. **`MIKA_VOICE` 的來源條款與 `converse` 的規則互相矛盾。**
   原文寫「back every one of them with a number or a source」與「traces to the context
   or the portfolio map」，但 `converse` 沒有編號 context 也沒有 portfolio map，它的規則是
   「只從 transcript 回答」。更要緊的是 `converse` 只跑 `stripUngroundedLinks`，沒有
   `stripInvalidCitations`，所以被這條逼出來的 `[1]` 會原樣送到訪客眼前。
   改成不指名來源，並明說這個區塊不新增任何引用要求。

2. **`personalRedirect` 違反 persona 自己的 emoji 規則。**
   規則原文禁止「declining a genuine request」時用 emoji，而問「他幾歲」確實是 genuine
   request 被 decline，三語卻都帶著 😊。判定是規則寫得太粗：作品集查不到與拒絕越界請求
   要讀起來直白，擋注入與把私人問題轉交本人這兩個場合的溫度本身就是內容。規則改寫成
   四個場合各自指名，測試也拆成兩條，各自釘住「零個 emoji」與「恰好一個 emoji」。

3. **`rag/nodes.ts` 的 output-guardrail 罐頭回覆漏掉了。**
   它是第三個不經模型的字串（另外兩個在 `triage.ts`），先前是無名的，zh-TW 版還帶著
   半形逗號。連同 scope-lock 裡給模型看的拒答範例一起改成她的語氣。

4. **`MIKA_IDENTITY` 內部自相矛盾。** 「She is the chat launcher…」出現在
   「never describe Mika in the third person」的前一句。這段是從 `nodes.ts` 原封搬過來的，
   所以矛盾也跟著搬。改成第一人稱。

5. **內容題只有開場句，沒有結尾句。** 這是驗收標準 4 的一半，兩個 reviewer 都指出。
   52 條補上三語結尾句（另 5 條本來就以邀請收尾），並補一條測試釘住。

6. **15 條開場句與內容首句重複。** 「四條原則，他是真的照著做。」接「Charles 有四個工作原則：」
   這類。改寫成帶她的態度而不重述答案。

7. **6 處日文開場句掉了主語，把 Charles 的事變成她的事。**
   「これは自分のために作ったツールなので」會讀成 Mika 為自己做的。日文可以省略主語，
   而省略的主語會接到前一個說話的人身上，所以這類句子必須顯式寫出「彼」。

### 已知限制，刻意留著

- **開場句與結尾句的測試對「內容段本身就很短」的條目無效。**
  實測（不是估計）：刪掉開場句在 171 個答案／語言組合中有 53 個不會被抓到，刪掉結尾句有 33 個。
  `philosophy` 的「Charles works by four principles:」只有 33 字元，低於 en 的 90 字元天花板。
  測試的註解現在帶著這兩個數字。要真正釘死，得把 opener／closer 從 `answers` 字串裡抽成獨立欄位，
  讓型別在編譯期強制；那會改變 `answers` 的語意並牽動 ingest 與既有測試，本輪不做。
  翻開條件：再出現一次「新條目忘了寫語氣句」。
- **`injectionRefusal` 的日文用常体，其他說明類文案用敬体。**
  這是 100% 強度那一層，情緒句用常体貼近錄音，符合分層表。

## 2026-08-26 雙 reviewer 第三輪：兩項事實錯誤，然後停手

第二輪的六項全部確認關閉，六個驗收標準全部 MET。第三輪剩兩項，都不是功能缺陷：

1. **「28 個錄音全部說 あたし」是假的。** 實測 `scripts/voice_lines.py`：28 個日文 clip 裡
   3 個含「あたし」（greet-5、greet-9、intro-1），0 個含「私」，其餘 25 個根本沒有第一人稱。

### 為什麼停在這裡

CLAUDE.md 定的規則是「同樣的發現連兩輪出現、或總計三輪未收斂就停止自行修正」。三輪的
發現數是 13 → 6 → 2，功能面在第二輪就收斂了，第三輪剩下的兩項都是**我在文件與註解裡
宣稱了程式碼沒做到的事**。這個類別三輪都出現過（第一輪是測試註解的天花板宣稱、第二輪是
changelog 與本檔的日文人稱、第三輪是錄音與 ceiling 的數字），每次的具體實例不同，每次都修好，
但它是這次工作真正的失敗模式，值得記在這裡而不是再派第四輪。

補救方式已經內建：本檔與所有註解裡引用的數字，現在一律先跑一次量測再寫，量測腳本留在
scratchpad。剩下的判斷交給使用者。
