# vrm1to0-0906：Phase 3.5 VRM 1.0 → 0.x 入口轉換的收據

骨架泛化計畫的第五步（Phase 0–3 之後、Phase 4 之前）。Phase 0 讓 `humanoid.py` 兩版都讀，
但 build 端的 writer（`build.py`／`customise.py`／`twintail.py`）只寫 `extensions.VRM`：
`materialProperties`、`blendShapeMaster`、`secondaryAnimation`。一具 VRM 1.0 底模進
`make.py --base` 會在第一個 writer 撞 KeyError。改法是在門口轉一次：`vrm1to0.py` 把 1.0
的 JSON 改寫成 0.x（binary chunk 原樣複製），`make.py` 第 0b 步呼叫它並把 `base` 換成轉出的
檔，之後的每一步（partition、五道 gate、`verify.report`）讀的都是 0.x。

## 規則從哪裡來

轉出的 0.x 檔由 three-vrm 3.x 用它載 VRoid 檔的同一組 v0 importer 讀，所以每條規則都是
那些 importer 的反函數，逐行對照 `node_modules/@pixiv/three-vrm/lib/three-vrm.module.js`：

| 區塊 | three-vrm 的 v0 讀法 | 轉換寫法 |
|---|---|---|
| humanoid | `VRMHumanoidLoaderPlugin._v0Import`：list of `{bone, node}`，`thumbBoneNameMap` 把 0.x 的 `leftThumbProximal`→`leftThumbMetacarpal`、`leftThumbIntermediate`→`leftThumbProximal` | dict→list、拇指名反向改回 0.x 拼法；1.0 檔若已用舊拼法（`existsPreviousThumbName`）不動 |
| 朝向 | `VRMUtils.rotateVRM0`：0.x 場景轉 π 對齊 +Z | 所有 scene root 掛到一個新節點 `vrm0-root`（rotation `[0,1,0,0]`）底下；用新節點而非改 root 自身的 rotation，因為 root 可能就是 humanoid 骨，retarget 會覆寫它的 local rotation |
| 材質 | `VRMMaterialsV0CompatPlugin._parseV0MToonProperties`：`_Color` 等經 `pow(v, 2.2)`、`_OutlineWidth × 0.01`、`toony1 = lerp(toony0, 1, 0.5+0.5·shift0)`、`shift1 = −shift0 − (1−toony1)`、`_MainTex` 的 offset.y = 1 − scale.y − offset.y、renderQueue 依序排成 offset | 各取反函數：`pow(v, 1/2.2)`、`÷0.01`、`shift0 = −shift1 − (1−toony1)` 再 `toony0 = (toony1 − t)/(1 − t)`（t = 0.5+0.5·shift0）、y 翻回、queue 依 alphaMode 給 2000／2450／3000+offset／2501+offset。`pbrMetallicRoughness.baseColorFactor` 改寫成與 `_Color` 相同的數（VRoid 0.x 匯出就是這樣，`customise.tint` 兩個一起寫、`render.py` 讀 baseColorFactor）。沒有 MToon 的材質寫 `VRM_USE_GLTFSHADER` 佔位，維持 `materialProperties[i]` 對 `materials[i]` |
| 表情 | `VRMExpressionLoaderPlugin._v0Import`：`weight × 0.01`、`v0v1PresetNameMap`、bind 的 `mesh` 找所有畫它的 node、`materialValues` 的 `_MainTex_ST` 讀 `[sx, sy, ox, oy]` 並 `oy = 1 − oy − sy` | `weight × 100`、preset 名反查（`surprised` 在 0.x 沒有名字 → `presetName 'unknown'`，名字保留）、node → `nodes[node].mesh`、`materialColorBinds` → `materialValues`（`v0ExpressionMaterialColorMap` 反向）、`overrideBlink/LookAt/Mouth` 捨棄並回報 |
| 彈簧 | `VRMSpringBoneLoaderPlugin._v0Import`：collider offset `z` 取負（「z is opposite in VRM0.0」）、`stiffiness` 拼法、每個 boneGroup 一組參數、`root.traverse` 每個節點一個 joint | offset.z 取負；1.0 的 collider group 可跨 node，0.x 一組一個 node → 按 node 拆組、spring 的 `colliderGroups` 展開成所有拆出的組；capsule → 沿 offset→tail 排球（間距 ≤ 半徑）；每條 1.0 spring 一個 boneGroup，取根關節參數，逐關節不同時回報 |
| meta／lookAt／firstPerson | `VRMMetaLoaderPlugin._v0Import` 原樣讀；`VRMLookAtLoaderPlugin._v0Import` 的 `firstPersonBoneOffset.z` 取負、`lookAtTypeName 'BlendShape'` 時 yRange 預設 1 否則 10 | 1.0 enum 對到 0.x enum（`avatarPermission`／`commercialUsage`／布林→Allow/Disallow）、`thumbnailImage`（image）→ `texture`（找 source 相同的 texture，沒有就補一個）、offset.z 取負、`rangeMap*` → `lookAt*` 帶 VRoid 的固定 curve |

0.x 沒有的東西一律**捨棄並印出**（`ensure_vrm0` 的「捨棄：」「近似：」行）：`VRMC_node_constraint`、
表情 override、extended collider、逐關節不同的彈簧參數、capsule 近似、matcap 顏色綁定。

## 夾具：兩個方向

- `vrm1to0_test.doc1()`：手寫的 1.0 文件，每個數字都挑成 0.x 端的期望值能直接寫在旁邊
  （collider z=0.3 → −0.3、outlineWidthFactor 0.002 → `_OutlineWidth` 0.2、textures 與 images
  故意不同序，讓「把 image index 當 texture index 抄過去」會被抓到）。
- `vrm1to0_test.twin()`：0.x → 1.0，**逐行 port three-vrm 的 v0 importer**（compat plugin 的
  材質公式含 renderQueue 排序、表情 `×0.01` 與 preset map、collider z 翻號、humanoid 拇指改名、
  scene root 掛在轉 π 的 `vrm1-root` 下，與 `rigProbe.test.ts` 的 `vrm1Twin` 同一做法）。
  轉換器的正確性因此是「對 three-vrm 的讀法求反」而不是「對自己求反」；兩個方向若同時寫錯
  同一個符號，`doc1()` 那組字面值測試會抓到（V3／V7／V10／V22 各自紅）。
- `RoundTrip`：`convert(twin(mika-pink.vrm))` 對原檔比：骨架（`compare` 容差 1e-9）、每 mesh 的
  skin、彈簧（每根 root 的參數與 collider 組、offset 到 1e-9）、材質（管線讀的每個鍵到 1e-9、
  `_ALPHABLEND_ON`／`_ALPHATEST_ON`／`_NORMALMAP` 的有無、`baseColorFactor`、alphaMode）、
  表情（presetName 序列、custom 名字、binds、materialValues）、firstPerson 四張 map、meta 六個欄位
  與縮圖來源 image，且 report 兩個清單皆空。
  兩處刻意不比：renderQueue 數字（three-vrm 把 0.x 的 queue 排名成 offset，眼睫毛的 4500 會回成
  3000；只比排名順序）、`_OutlineColorMode`（mode 0 配任何 mix 與 mode 1 配 mix 0 算圖相同；比
  有效 mix）。preset 表情的 0.x `name` 也會變（`'A'` → `'aa'`）：three-vrm 對 preset 用 preset
  名當表情名，不看 group name，網站的 `avatarMode.ts` 用的就是 `aa`／`happy`；custom 名
  （`Surprised`／`Extra`）逐字保留。

## 整條管線：從孿生建出的檔與從 baseline 建出的檔 vertex sha 相同、四視角 0 像素
